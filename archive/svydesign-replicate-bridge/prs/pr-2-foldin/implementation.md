## The one existing assertion that had to change

Task 9 said to edit no existing block. One had to change, because the spec
makes its assertion false.

PR 1's block R-4, `"from_svydesign() writes one double column per replicate
for an uncompressed source"` (`test-conversion.R:1264` before the edit), built
its source with `survey::as.svrepdesign(type = "JKn", compress = FALSE)`. That
source reports `combined.weights` `FALSE`, so step 9 now multiplies. The block
asserted the stored column equals the raw source column at `tolerance = 0`,
which is the pre-fold-in value:

```r
expect_equal(
  d@data[[d@variables$repweights[[j]]]],
  as.numeric(rep_mat[, j]),
  tolerance = 0
)
```

Spec §III.2 step 9 and §VI property 10 are normative and say the stored column
is the source column "times the base weight when the source reported
replication factors". The expectation was corrected to
`as.numeric(rep_mat[, j]) * as.numeric(sv$pweights)` at `tolerance = 1e-12`,
with a comment naming step 9. Nothing else in the block changed: it still
tests the column count, the names, the `..ncol..` arithmetic and the `double`
type, which is what its title claims.

No HOLD was raised for this, because the spec resolves it without a judgement
call. Flagging it because it breaches the letter of task 9.

The second edit to existing content is a comment only, no assertion: R-3's
header said "The fold-in that removes it is not in this change", which this
pull request makes false. It now points at R-11.

## Notes for tester

- **The installed `air` is a CLI, not an R package.** `air::format_package()`
  fails with "there is no package called 'air'"; the binary is at
  `~/.local/bin/air`. Worse, `air format R tests` reformatted 24 files outside
  the write surface — `test-analysis-diffs-helpers.R` alone by 619 lines — so
  the installed CLI version disagrees with whatever last formatted the repo.
  All 24 were reverted with `git checkout --`; only the three files in the
  write surface remain. `air format --check` is clean on them. Someone should
  pin the `air` version before the next formatting pass.
- **A full `devtools::test()` run rewrites 29 `_snaps/*.md` files** with
  different line endings. `git diff` reports no content change for them (the
  endings normalize away) but `git status` flags all 29 as modified. They were
  restored with `git checkout -- tests/testthat/_snaps/`. This is the known
  `_snaps/` line-ending issue from `archive/test-suite-simplification/`; it is
  not caused by this change. Check `git status` after any full run.
- **`survey::svrepdesign()` refuses an `NA` in `repweights`** — it stops with
  "Missing values not allowed in 'repweights'". So R-15 cannot build such a
  source through the constructor; it builds a clean design and then assigns
  `sv$repweights[2L, 1L] <- NA` on the built object. The route reads the field,
  not the call, so this exercises the real code path. There is no reachable
  constructor route to an `NA` replicate weight.
- **`x$pweights` carries names** (the data frame row names). An expectation
  written as `as.numeric(rep_mat[, j]) * sv$pweights` inherits them and fails
  against the unnamed stored column on the names attribute alone. Every such
  expectation wraps the base weight in `as.numeric()`.
- **`get_means()` on a design with fewer than 30 rows in a cell** raises
  surveycore's AAPOR small-cell warning, which would push the suite's warning
  count above 256. Both oracle-parity blocks (R-11, R-22) therefore use
  `n = 40L`. A reviewer adding a parity block to this file should do the same.
- **Fold-in parity is exact, not approximate.** Measured relative SE
  difference against the `survey` oracle was 0 for JKn, 4.4e-16 for a second
  JKn draw, 0 for bootstrap and -5.6e-16 for the R-22 case; CI bound
  differences were 0 to 1.7e-16. The 1e-8 and 1e-6 tolerances have several
  orders of magnitude of headroom.
- **`survey::svrepdesign()`'s `combined.weights` heuristic warning did not
  fire** on any source built here, on this `survey` version — the guessing
  branch needs a mean replicate weight above 5. The `suppressWarnings()`
  wrappers are precautionary, per the task, not load-bearing today.
- Step 9 sits before step 10 as the spec orders it, but the ordering is not
  observable: the fold-in touches `rep_mat` and the base weight search reads
  `data`. The ordering that does matter — step 10 before step 11 — was already
  correct from PR 1, and R-22 now pins its numerical consequence.
