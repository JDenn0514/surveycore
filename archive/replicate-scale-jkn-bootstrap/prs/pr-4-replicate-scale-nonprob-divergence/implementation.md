## Summary

- Two oracle blocks in `tests/testthat/test-variance-replicate.R` drive the
  variance engine at `type = "bootstrap"` with one replicate column, where
  the stored scale is `1 / (R - 1)` at `R = 1` and so `Inf`. One block uses a
  frame whose replicate estimate moves, and both surveycore and `survey`
  return an infinite standard error and two infinite bounds. The other uses a
  frame whose replicate estimate is bit-identical to the full-sample
  estimate, and both sides return `NaN` for the standard error and both
  bounds.
- Two cross-constructor blocks in `tests/testthat/test-constructors.R` pin
  the relationship between `as_survey_replicate()` and `as_survey_nonprob()`.
  They agree at `1` for `"JKn"`, and they diverge for `"bootstrap"`: the
  replicate design stores `1 / (R - 1)`, the nonprob design stores `1 / R`,
  and the ratio of the two standard errors is `sqrt((R - 1) / R)`.
- The `as_survey_nonprob()` `@details` paragraph now names `survey`'s
  bootstrap value `1 / (R - 1)`, names `as_survey_replicate()` as the
  constructor that matches it, gives the reason this constructor keeps
  `1 / R`, and states the fall of 2.5% at `R = 20`. The Wu (2022) and Chen
  et al. (2021) citation is unchanged.
- Every stored scale is asserted against a literal. No assertion compares one
  side's stored scale against the other side's.

## Measurements taken during the build

`survey` 4.5 under R 4.6.1 (Windows).

| Frame | surveycore scale | surveycore SE | `survey` scale | `survey` SE | conditions |
|---|---|---|---|---|---|
| A — one replicate column, own weights | `Inf` | `Inf`, bounds `-Inf`/`Inf` | `Inf` | `Inf`, bounds `-Inf`/`Inf` | none on either side |
| B — one replicate column copied from the base weights | `Inf` | `NaN`, bounds `NaN` | `Inf` | `NaN`, bounds `NaN` | none on either side |

`survey::svrepdesign()` raised no warning and no error on either frame, so no
condition is asserted by message text. `expect_no_warning()` wraps the
`svrepdesign()` call in both blocks and `expect_no_condition()` wraps each of
the four estimate calls and the two default-scale constructor calls.

**Frame B needs whole-valued data.** The full-sample path computes
`sum(y * w) / sum(w)` and the replicate path computes
`as.numeric(y %*% rep_mat) / colSums(rep_mat)`. The two summation orders agree
bit for bit only while every partial sum is exact. A first attempt at frame B
used `runif()` weights with `repwt_1` copied from `wt`; the deviation landed
one ulp from zero, the premise standard error read `1.78e-15` rather than `0`,
and the product was `Inf` and not `NaN`. `survey` returned `NaN` on that same
frame, so the two sides disagreed. The shipped frame draws whole-number `y1`
and whole-number weights, the deviation is exactly zero, the premise standard
error is exactly `0`, and both sides return `NaN`. The block carries this as a
comment, because a later edit that switches the fixture to real-valued
weights turns the block silently into a test of the other outcome.
