## I. Scope

### In

| # | Deliverable |
|---|---|
| 1 | `as_survey_replicate()` gains the argument `rho`, the Fay shrinkage factor |
| 2 | `type = "Fay"` requires `rho`; the Fay scale becomes `1 / (R * (1 - rho)^2)`; a supplied `scale` is discarded with no condition |
| 3 | `rho` supplied with any other type raises a typed warning and is discarded |
| 4 | Every `survey_replicate` design built by surveycore stores the key `rho` in `@variables`: the number for Fay, `NULL` otherwise |
| 5 | `as_svydesign()` passes the stored `rho` to `survey::svrepdesign()`; the scale inversion from PR #250 is deleted; CB-4 is restated for a Fay design with no usable stored `rho` |
| 6 | `from_svydesign()` stores `survey`'s `rho` for a Fay design and `NULL` for every other type |
| 7 | `print()` and `summary()` of a Fay design show `rho` |
| 8 | Documentation: roxygen for both classes and the constructor, the Judkins citation, the vignette, `NEWS.md`, `CLAUDE.md`, and the oracle rule in `.claude/rules/testing-surveycore.md` |
| 9 | `as_survey_twophase()` refuses a `survey_replicate` phase 1 with a new typed error (S9, §IX). This item does not depend on `rho` or on items 1 to 8, so it can ship in a PR of its own |

### Out

- **Legacy Fay objects in the analysis functions (S7).** A Fay design saved
  before this change has no `rho` key and keeps its stored `1/R` scale.
  `get_means()` and the other analysis functions use that scale and raise no
  condition. `NEWS.md` tells users to rebuild Fay designs.
- **A replicate key check in `test_invariants()` (S4).**
- **The `scale` and `rscales` rules for BRR, JK2, ACS and
  successive-difference (S2).** They stay with issue #255. That includes
  D10's change that stops the export route passing `scale` for the types
  `survey` overrides.
- **`as_survey_nonprob()`.** It refuses `type = "Fay"` today and keeps doing
  so. Its `@variables` lists do not gain a `rho` key.
- **The class validator of `survey_replicate`.** It does not check `rho`. The
  exported `survey_replicate()` constructor keeps its untyped `variables`
  list.
- **Consistency of a stored `scale` with a stored `rho`.** A design built
  through `survey_replicate()` or edited by hand can hold a Fay scale that
  does not equal `1 / (R * (1 - rho)^2)`. No function checks this.
- **Detection of a wrong `rho`.** surveycore cannot tell whether the `rho`
  the caller passes is the value that built the replicate columns.
- **A check of the Fay design layout.** The Fay scale assumes a
  two-PSU-per-stratum layout with Hadamard-balanced half samples, which
  surveycore does not check; the scale is exact for totals and first-order
  for means and ratios.
- **Replicate-weight generation.** surveycore does not build Fay replicate
  weights.
- **`update_design()` and a changed replicate count (issue #300).** It
  copies `@variables` and keeps `rho`. It does not recompute the scale when
  `repweights =` changes the replicate count, for any type. Issue #300 owns
  that defect (S10).
- **Phase-1 variance for a replicate phase 1.** §IX refuses the design. An
  implementation of its variance is not part of this work.

### Functions added

```r
# R/utils.R — used by R/core-constructors.R and R/methods-conversion.R.
# TRUE when rho is one finite number in [0, 1) with no dim attribute;
# FALSE otherwise. Never errors.
.is_valid_rho <- function(rho) {
  is.numeric(rho) &&
    is.null(dim(rho)) &&
    length(rho) == 1L &&
    is.finite(rho) &&
    rho >= 0 &&
    rho < 1
}
```

The predicate lives in `R/utils.R` because two files call it
(`.claude/rules/code-style.md` §Internal helpers). The `dim()` test refuses a
1 x 1 matrix and a 1 x 1 x 1 array, which pass every other test.

```r
# R/methods-print.R — used by print() and summary() for survey_replicate
# only, so it stays in this file. Returns the rho to show for a Fay design
# with a usable stored rho, else NULL.
.fay_rho_to_print <- function(x) {
  rho <- x@variables[["rho"]]
  if (!identical(x@variables$type, "Fay") || !.is_valid_rho(rho)) {
    return(NULL)
  }
  rho
}
```

Both methods call `.fay_rho_to_print()` once. When it returns `NULL` they
print nothing new. Otherwise they build both pieces from its value: the
`, rho = {rho}` suffix and the `Rho:` line. So the gating condition is
written once (§VII).

## III. `as_survey_replicate()`

### Signature

As in §II.

### Arguments

Unchanged arguments keep their current meaning. Changes:

| Argument | Type | Default | Meaning |
|---|---|---|---|
| `rho` (fifth formal, after `type`) | numeric scalar or `NULL` | `NULL` | The Fay shrinkage factor: the replicate weights of a Fay design multiply one half-sample by `2 - rho` and the other by `rho`. Required when `type = "Fay"`. Valid range `[0, 1)`; `0` gives BRR. Integer input is accepted; a value with a `dim` attribute is refused. Ignored with a warning for every other type |
| `scale` (now the sixth formal) | numeric or `NULL` | `NULL` | Unchanged for every type except Fay. For `type = "Fay"` a supplied value is discarded with no condition, and the scale is always `1 / (R * (1 - rho)^2)` |

### Order of checks

The formal order (S11) changes no check order. `rho` is evaluated only in
step 2.

1. Every check that runs today runs first, in its current order: `type` and
   `fpctype` through `match.arg()`, the data frame, the column selections,
   the weights, the replicate columns, the FPC column, and `rscales`. So an
   empty frame, a single-row frame or a bad `rscales` length raises its
   existing error even when `rho` is also wrong.
2. Then the `rho` rules:
   - `type == "Fay"` and `rho` is `NULL`: abort with
     `surveycore_error_fay_rho_missing` (FR-1).
   - `type == "Fay"` and `.is_valid_rho(rho)` is `FALSE`: abort with
     `surveycore_error_fay_rho_invalid` (FR-2).
   - `type == "Fay"` and `rho` is valid: the stored `rho` is
     `as.double(rho)` (an unnamed double of length 1), and the scale is
     `1 / (n_rep * (1 - rho)^2)`, whatever `scale` holds. No condition.
   - `type != "Fay"` and `rho` is not `NULL`: warn with
     `surveycore_warning_rho_ignored` (FR-3); the stored `rho` is `NULL`.
     The value of `rho` is not checked (P2).
   - `type != "Fay"` and `rho` is `NULL`: no condition; the stored `rho` is
     `NULL` (D8).
3. Then the default scale for the other eight types, as today. The `Fay`
   entry is deleted from the default-scale switch: no `Fay` branch remains
   in it. The Fay scale is set in step 2, because it does not depend on
   whether `scale` is `NULL`.

`n_rep` is the number of replicate columns `repweights` selects.

### Returns

A `survey_replicate` object, as today. `@variables` holds, in this order:

```r
list(
  weights = weights_var,
  repweights = repweights_vars,
  type = type,
  scale = scale,
  rscales = rscales,
  fpc = fpc_var,
  fpctype = fpctype,
  mse = isTRUE(mse),
  rho = rho,
  visible_vars = NULL
)
```

`rho` is present for every type. For Fay it is a double in `[0, 1)`; for
every other type it is `NULL`. For Fay, `scale` is the double
`1 / (n_rep * (1 - rho)^2)`, computed with that expression. `type` stays
`"Fay"` at `rho = 0` (P5).

### Edge cases

| Input | Behaviour |
|---|---|
| `rho = 0`, Fay | Accepted. Scale `1 / n_rep`, the BRR scale. `type` stays `"Fay"` |
| `rho = 0L` or other integer in range | Accepted; stored as double |
| `rho` just below 1, for example `0.999` | Accepted. Scale `1 / (n_rep * 0.001^2)` |
| `rho = 1`, `rho > 1`, `rho < 0` | FR-2 |
| `rho = NA`, `NA_real_`, `NaN`, `Inf`, `-Inf` | FR-2 |
| `rho` of length 0 or length 2 or more | FR-2 |
| `rho = TRUE`, `rho = "0.5"`, a factor, a list | FR-2 |
| `rho = matrix(0.3)`, `rho = array(0.3, c(1, 1, 1))` | FR-2: a value with a `dim` attribute is refused |
| `rho = c(a = 0.3)` | Accepted; stored unnamed |
| `rho = NULL` passed explicitly | The same as not passing it |
| Fay with a supplied `scale` | The supplied value is discarded; no condition |
| Fay with `rscales` | `rscales` is kept and used, as for every type |
| Fay with `mse = FALSE` | Accepted; `mse` only moves the centre of the replicate deviations |
| Fay with one replicate column | Accepted. Scale `1 / (1 - rho)^2` |
| Empty data frame | The existing `surveycore_error_empty_data`, before any `rho` rule |
| Single-row data frame | The existing `surveycore_error_single_row`, before any `rho` rule |
| All-`NA` outcome column | Not a constructor input. The analysis functions treat a Fay design as they treat any replicate design |
| Zero values in a replicate column | Unchanged; the weights rules are the existing ones |
| Single-level grouping | Not a constructor input; unchanged |
| Degenerate strata | Not reachable: a replicate design reads no strata |

### Domain estimation and grouping

Unchanged. The variance for a Fay design differs from the variance for a BRR
design only by the stored scale. Domain estimation after `filter()` and
grouped estimation work as for every replicate type.

## V. `from_svydesign()` — replicate route

The route builds `@variables` with the key `rho`, between `mse` and `fpc` or
in any position; the order of keys is not part of the contract.

| `survey` object | Stored `rho` |
|---|---|
| `x$type == "Fay"` | `x$rho`, copied unchanged (P4) |
| any other type | `NULL`, whatever `x$rho` holds (S8) |

Notes:

- `survey::as.svrepdesign(type = "BRR")` stores `$rho = 0`, and
  `survey::svrepdesign(type = "BRR", rho = 0.3)` stores `$rho = 0.3`. Both
  import with `rho = NULL`.
- `survey::as.svrepdesign(type = "BRR", fay.rho = 0.3)` relabels the object
  as `"Fay"`, so it imports as a Fay design with `rho = 0.3`.
- The stored scale is still `x$scale`, copied unchanged. The imported
  standard errors do not move.
- A Fay object whose `$rho` is `NULL` or outside `[0, 1)` imports without a
  condition. Its export is refused (§VI).

No new condition.

## VI. `as_svydesign()` — replicate route

### VI.1 Behaviour

1. Delete the recovery of `rho` from the stored scale, with its comments.
2. For `@variables$type == "Fay"`:
   - When `.is_valid_rho(x@variables$rho)` is `FALSE` — the key is absent,
     `NULL`, or holds a value outside the rule — abort with
     `surveycore_error_fay_rho_unrecoverable` (§VI.3). A missing key reads
     as `NULL`.
   - Otherwise pass `rho = x@variables$rho` to `survey::svrepdesign()`, and
     pass no `scale`, as today.
3. For every other type pass `rho = NULL`. Never pass a stored `rho` for a
   non-Fay type.
4. Everything else in the route is unchanged: the empty-replicate refusal
   runs first, the FPC drop and its warning follow the Fay check, and the
   `scale` argument rule for the other types is unchanged (§I Out).

The exported object reproduces surveycore's standard error for a Fay design
built by `as_survey_replicate()`, because `survey` computes the same scale
from the same `rho`.

## VII. `print()` and `summary()` for `survey_replicate`

Both methods decide what to show by one call to `.fay_rho_to_print(x)`
(§II). It returns the stored `rho` for a Fay design whose stored `rho`
passes `.is_valid_rho()`, and `NULL` otherwise. When it returns a value:

- The class line of `print()` and the type line of `summary()` add
  `, rho = {rho}` after the replicate count.
- The `Scale:` line of the full print and the `Scale:` line of `summary()`
  are each followed by a `Rho:` line in the same style.

For every other type, and for a Fay design with no usable `rho`, the output
is unchanged, byte for byte.

`rho` renders with `{.val {rho}}`, the markup that `Scale:` already uses.

In the examples below, the rule lines, bullets and tibble body are drawn by
cli and tibble exactly as today. Only the class or type line and the new
`Rho:` line differ from a BRR design's output.

Console output for a Fay design with 10 replicate columns and `rho = 0.5`
(scale `0.4`). Default print:

```
── Survey Design ───────────────────────────────────────────────────────────────
<survey_replicate> (FAY, 10 replicates, rho = 0.5)
Sample size: 200

# A tibble: 200 × 18
...
```

The design section of `print(x, full = TRUE)`:

```
── Design specification ──

• Weights: wt
• Replicates: 10 FAY replicate weight column(s)
• Scale: 0.4
• Rho: 0.5
• MSE: TRUE
• FPC: not specified
```

The lines of `summary(x)` that change:

```
Type: replicate weights (FAY, 10 replicates, rho = 0.5)
...
Scale: 0.4
Rho: 0.5
MSE: TRUE
```

The `survey_nonprob` print also has a `Scale:` line. A nonprob design never
has type Fay, so that method does not change.

## IX. `as_survey_twophase()` refuses a `survey_replicate` phase 1

Decision S9. This section does not depend on `rho` or on §III to §VIII. The
implementation plan can put it in a PR of its own, in either order relative
to the `rho` work.

### IX.1 Why

The phase-1 variance code of a two-phase design reads only the phase-1
`strata`, `ids` and `fpc` keys. A replicate phase 1 has none of them, so the
code treats every row as its own PSU and never reads the replicate columns
or the replicate scale. The standard error of such a design is wrong for
every replicate type. `survey` has no two-phase design with a replicate
phase 1. This reverses PR #74, which admitted a replicate phase 1.

### IX.2 Behaviour

- Signature: unchanged.
- Order of checks: the existing check that `phase1` inherits `survey_base`
  (`surveycore_error_phase1_class`) runs first. Directly after it, when
  `S7::S7_inherits(phase1, survey_replicate)` is `TRUE`, abort with
  `surveycore_error_twophase_replicate_phase1`. Both checks run before any
  check on `subset`, so a replicate phase 1 with a missing or bad `subset`
  raises the replicate refusal.
- The refusal fires for every replicate type, Fay included, and whatever the
  design's `rho`.
- A `survey_taylor` phase 1 and a `survey_nonprob` phase 1 are not refused
  by this check; they reach the same later checks as today.

## Quality gates

1. `as_survey_replicate(type = "Fay", rho = r)` stores `rho = r` and
   `scale = 1 / (R * (1 - r)^2)` for every valid `r`. Its formal names, in
   order, are `data`, `weights`, `repweights`, `type`, `rho`, `scale`,
   `rscales`, `fpc`, `fpctype`, `mse`, `calibration`.
2. `get_means()` on a Fay design agrees with `survey::svymean()` on a
   `survey::svrepdesign(type = "Fay", rho = r)` built from the same columns,
   for the SE and both confidence bounds, at several `r` including 0. The
   bounds agree only while both packages build the interval from the normal
   approximation: surveycore sets the degrees of freedom to `Inf` on the
   replicate path, and `survey`'s `confint()` defaults to `df = Inf`. A
   change to the replicate degrees of freedom on either side moves every
   bound, and the Fay comparison must then be revisited in the same PR.
3. Every error and warning in §III, §VI and §IX is raised with its class and
   its register template.
4. Every `survey_replicate` built by `as_survey_replicate()` or
   `from_svydesign()` has the key `rho`.
5. No existing snapshot of a non-Fay design changes.
6. `R/variance-replicate.R` is byte-identical before and after the work.
7. No text in `R/`, `man/`, `vignettes/`, `NEWS.md` or `CLAUDE.md` says that
   surveycore recovers or derives `rho` from the scale, or names `fay_rho`.
8. No text in `R/` or `man/` cites Judkins (1990) in the *Journal of the
   American Statistical Association*.
9. `.claude/rules/testing-surveycore.md` names no sanctioned exception.
10. `as_survey_twophase()` raises
    `surveycore_error_twophase_replicate_phase1` for a `survey_replicate`
    phase 1 of every type, and does not raise it for a `survey_taylor` or
    `survey_nonprob` phase 1. No text in `R/` or `man/` says a replicate
    phase 1 is accepted.
11. `R CMD check` passes with the package's usual bar:
    `.claude/rules/r-package-conventions.md` §Package check hygiene.

## Integration

- **surveytidy.** Its verbs copy `@variables` and never rebuild the list, so
  `rho` survives `filter()`, `select()`, `rename()` and `mutate()`. A verb
  that writes a new `survey_replicate` from parts must carry `rho`; none does
  today.
- **survey.** `as_svydesign()` output for a Fay design carries `$rho` equal
  to the stored value and `$scale` equal to `survey`'s own formula.
