# Changelog: docs/nrow-dim-stored-row-count

**Status:** Complete
**Date:** 2026-09-08

## Summary

Closes #236. Nothing user-facing said that `nrow()` and `dim()` on a survey
design report the **stored** row count rather than the in-domain count. PR
#238 registered the `dim()` method that makes those functions work, and its
spec deferred the note.

The gap matters because a domain filter keeps every row and marks membership
in a flag column. Only `subset()` removes rows. So an analyst who filters a
design to a subgroup and asks for its size gets the whole sample back:

```r
d_65 <- surveytidy::filter(d, age >= 65)
nrow(d_65)   # the stored row count, not the subgroup size
```

The stored count is the right answer, and it stays. The design question was
settled before the change:

- `nrow()` is not separable from `dim()`. Base R defines `nrow(x)` as
  `dim(x)[1L]`, so a domain-aware `nrow()` means a domain-aware `dim(x)[1]`
  beside a frame-width `dim(x)[2]`. The pair would describe two different
  objects and index nothing.
- `nrow(d) == nrow(survey_data(d))` is an invariant callers rely on.
  `survey_data(d)[seq_len(nrow(d)), ]` is correct today and would silently
  drop rows if `nrow()` shrank.
- A warning on a filtered design was considered and rejected. `nrow()` runs
  inside loops, inside surveycore, and inside packages that touch the object,
  so the warning would fire many times per session at no point the analyst
  chose. A warning marks a probable mistake; asking a design for its stored
  size is not one.

The precedent is `dplyr::group_by()`, not `survey::subset()`. `nrow()` on a
grouped data frame returns all rows, never the group sizes, and nothing warns.

No accessor was added. `get_effective_n()` already returns the in-domain
count in its `n` column — it reads the domain flag through `.apply_domain()`
at `R/analysis-effective-n.R:194`, takes `group`, and accepts a
`survey_collection`. The new `@details` names it, which is one point beyond
what the issue asked for: the issue pointed a reader at the printed
`Domain: n of N rows` line, and that shows a number without giving them a way
to compute one.

The block also picks up the second, unrelated fix the issue scoped into it.
`@param x` omitted `survey_nonprob`, which `survey_data()` accepts: it
validates with `S7::S7_inherits(x, survey_base)`, and `survey_nonprob`
inherits `survey_base`. The five copies of the same sentence in
`R/methods-conversion.R` are **untouched** — every one is correct today,
because `as_svydesign()` rejects a nonprob design, and #237 owns them.

**No behaviour changes.** Roxygen text and the regenerated `.Rd`.

## Changes

- Document that `nrow()` and `dim()` report the stored row count, not the
  in-domain count, and point at the `Domain: n of N rows` line that printing
  a filtered design shows
- Name `get_effective_n()` as the route to the in-domain count
- Document that `ncol()` counts the full stored width — the weight column,
  cluster and stratum ids, `fpc`, the domain flag when present, and every
  replicate-weight column — so it is neither a count of analysis variables
  nor comparable across design classes
- Document that `nrow()` is the unweighted sample row count, not a population
  estimate
- Add `survey_nonprob` to `@param x`
