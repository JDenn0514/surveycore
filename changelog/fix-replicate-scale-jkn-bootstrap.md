## Summary

Closes #253.

`as_survey_replicate()` gave `type = "JKn"` the delete-one jackknife factor
`(R-1)/R` and `type = "bootstrap"` the divisor `1/R`. Both are now `1` and
`1/(R-1)`. The other seven replicate types are unchanged.

| `type` | before | after | `survey::svrepdesign()` | `as_survey_nonprob()` |
|---|--:|--:|--:|--:|
| `"JKn"` | `(R-1)/R` | `1` | `1` | `1` |
| `"bootstrap"` | `1/R` | `1/(R-1)` | `1/(R-1)` | `1/R`, by decision D1 |

Both old defaults multiplied the variance by `(R-1)/R`, so a standard error
from either type rises by `1/sqrt((R-1)/R)` — 2.6% at `R = 20`. Measured on
the arc's own fixture at `R = 20`, the ratio of the nonprob standard error to
the replicate one is 0.97467943448089656 against
`sqrt(19/20) = 0.97467943448089633`.

**The two changes do not have the same standing, and this document does not
present them as one.** For JKn the old default was the wrong factor for every
stratified design: `(R-1)/R` is the factor of the *unstratified* delete-one
jackknife and names `"JK1"` only, while JKn is the stratified form, whose
per-stratum factor `(n_h - 1)/n_h` belongs in `rscales` and not in the overall
scale (Wolter 2007, *Introduction to Variance Estimation*, 2nd ed., §4.5–4.6).
For the bootstrap, `1/R` is the population form of the variance divisor and is
the value decision D1 keeps in `as_survey_nonprob()`, citing Wu (2022) and
Chen et al. (2021). D5 picks `1/(R-1)` for this constructor because `survey`
is its oracle, not because `1/(R-1)` is demonstrably more correct.

Two oracle blocks in `tests/testthat/test-variance-replicate.R` had pinned the
wrong numbers on purpose, each wrapping three assertions in
`testthat::expect_failure()` and closing with a ratio assertion against
`sqrt((R-1)/R)`. Those eight lines are gone and the six assertions now pass
unwrapped.

**This clears one of the two sanctioned exceptions in
`.claude/rules/testing-surveycore.md`, not both.** The other is the Fay block,
which compares nothing because `survey` refuses `type = "Fay"` without a
`rho` and surveycore has no `rho` argument. Issue #243 owns it.

## The E5 window

One input gets worse under this change, and it is deliberate.
`type = "JKn"` with `rscales = NULL` now stores `scale = 1` and keeps
`rscales = NULL`. The variance path reads a `NULL` `rscales` as `rep(1, R)`,
so that input computes an unweighted sum of squared deviations and **no
jackknife factor of any kind enters**. Before this change the same input at
least carried `(R-1)/R`.

`survey` refuses the input outright. Issue #255 moves
`as_survey_replicate()` to the same refusal and closes the window. It is
recorded here so a reviewer does not read it as a defect of this work.

## Changes

- `R/core-constructors.R` — `JKn = 1` and `bootstrap = 1 / (n_rep - 1L)` in
  the default `scale` switch of `as_survey_replicate()`, each with a short
  comment stating which value the line sets and why it is not the other
  candidate factor
- `R/core-constructors.R` — `@param scale` rewritten to carry eight facts,
  including the `rscales` correction for without-replacement PSU selection
  `(n_h - 1) * (1 - n_h/N_h) / n_h` with a key for both symbols, and the
  divergence from `as_survey_nonprob()`
- `R/core-constructors.R` — `@param rscales` gains a cross-reference to
  `@param scale`; `@param fpc` gains a clause stating it has no effect for a
  replicate design
- `R/core-constructors.R` — `as_survey_nonprob()` `@details` gains a note
  giving `survey`'s bootstrap value, naming `as_survey_replicate()` as the
  constructor that matches it, the reason this one keeps `1/R`, and the size
  of the gap as a fall of 2.5% at `R = 20`. The Wu (2022) and Chen et al.
  (2021) citation is unchanged
- `man/as_survey_replicate.Rd`, `man/as_survey_nonprob.Rd` — regenerated by
  `devtools::document()`
- `NEWS.md` — one bug-fix entry beside #242's, stating the direction and size
  of the move, the explicit `scale` values that reproduce the old numbers, and
  the different standing of the two corrections

The variance engine is untouched: `R/variance-replicate.R` is outside the
write surface and no line in it changed. No error class and no warning class
was added, and `plans/error-messages.md` is unchanged. `@variables` keeps all
nine keys; only the value of `scale` moves, for two `type` values.

## Verification

- `as_survey_replicate(type = "JKn")` with no `scale` stores `1`;
  `type = "bootstrap"` stores `1/(R-1)`. One block asserts all nine types'
  stored defaults against their own literals, so a later edit to any of them
  turns it red
- both oracle blocks pass unwrapped against `survey::svrepdesign()`:
  `survey`'s stored scale against a literal at 1e-8, the point estimate at
  1e-10, the standard error at 1e-8 and both confidence bounds at 1e-6, with
  `expect_no_warning()` on the `svrepdesign()` call
- a bootstrap design of one replicate column stores `Inf` and raises no
  condition. Its standard error is `Inf` where the replicate deviation is
  non-zero and `NaN` where the deviation is exactly zero, and `survey` reaches
  the same outcome on both frames. The zero-deviation frame uses
  integer-valued data, because with real-valued weights the deviation lands
  about 1.8e-15 off zero and the product is `Inf` rather than `NaN`
- `as_survey_replicate()` and `as_survey_nonprob()` store the same JKn scale
  and return the same mean and standard error; their bootstrap scales differ
  by the documented `sqrt((R-1)/R)`
- a `survey_twophase` design over a replicate `phase1` carries the stored
  scale unchanged; reverting either switch line reddens the matching two-phase
  assertion, which is what proves the two-phase constructor copies the value
  rather than recomputing it
- the full suite went from `[ FAIL 0 | WARN 256 | SKIP 4 | PASS 12005 ]` to
  `[ FAIL 0 | WARN 256 | SKIP 4 | PASS 12100 ]`. The 256 warnings are
  pre-existing AAPOR small-cell warnings and held at 256 through every PR
- `R CMD check --as-cran` gives 0 errors, 0 warnings and the two pre-approved
  notes throughout; `pkgdown::build_site()` builds; line coverage held at
  96.15% at every PR, against a 95% floor
- **no file under `tests/testthat/_snaps/` changed**, arc-wide, measured
