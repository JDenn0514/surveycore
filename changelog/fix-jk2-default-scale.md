## Summary

Closes #242.

`as_survey_replicate()` grouped `type = "JK2"` with `"JK1"` and `"JKn"` in the
default `scale` switch and gave all three the delete-one jackknife factor
`(R-1)/R`. `(R-1)/R` is wrong for JK2. JK2 is the paired jackknife: each
replicate is a half sample, and the per-stratum factors belong in `rscales`,
not in the overall scale. `survey::svrepdesign()` encodes that by fixing
`scale = 1` and `rscales = rep(1, R)` for JK2, and surveycore's own
`as_survey_nonprob()` already agreed with it. So the two surveycore replicate
constructors disagreed with each other about the same replicate type, and the
nonprob one was the one that agreed with `survey`.

Every JK2 design built without an explicit `scale` reported a standard error
low by `sqrt((R-1)/R)`. Measured on the issue's reproduction (`n = 60`,
`R = 8`, seed 11, `mse = TRUE`):

| Source | JK2 `scale` | SE of mean `y` |
|---|--:|--:|
| `as_survey_nonprob()`, `rscales = rep(1, 8)` | 1 | 0.124369313656 |
| `survey::svrepdesign()`, hardcoded | 1 | 0.124369313656 |
| `as_survey_replicate()`, before the fix | 0.875 | 0.116336840282 |
| `as_survey_replicate()`, after the fix | 1 | 0.124369313656 |

Ratio of the third row to the second: 0.935414346693, which is
`sqrt(0.875)` to twelve digits.

No test caught it because no test compared
`as_survey_replicate(type = "JK2")` against `survey::svrepdesign()`
numerically. The block named `JK2 default scale = 1 exactly` asserts the
stored value on `as_survey_nonprob()`, so it never read the replicate
constructor's `0.875`.

## Changes

- `R/core-constructors.R` — `JK2 = 1` in the default `scale` switch of
  `as_survey_replicate()`, with a comment stating why the delete-one factor
  does not apply
- `R/core-constructors.R` — the `@param scale` roxygen listed JK2 with JK1 and
  JKn. It now lists JK2 with `"other"` at `1`, and says the per-stratum
  factors belong in `rscales`
- `man/as_survey_replicate.Rd` — regenerated by `devtools::document()`
- `NEWS.md` — bug-fix entry stating the size and direction of the move, and
  how to reproduce the old numbers

`rscales` is untouched. `as_survey_replicate()` still defaults it to `NULL`,
which the replicate variance engine reads as `rep(1, R)` — the value `survey`
forces for JK2. `JKn` is untouched: it is a separate question from #242 and
no measurement here covers it.

## Verification

- `as_survey_replicate(type = "JK2")` with no `scale` stores `scale = 1`
- `get_means()` on that design matches `survey::svymean()` on a hand-built
  `survey::svrepdesign(type = "JK2", mse = TRUE)` from the same columns:
  point estimate to 1e-10, SE to 1e-8, CI bounds to 1e-6
- `as_survey_replicate()` and `as_survey_nonprob()` return the same mean and
  the same SE for JK2 on the same frame
- No snapshot depends on the JK2 scale; `_snaps/` is unchanged
