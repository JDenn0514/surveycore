# Changelog: docs/haven-class-attribute-test

**Branch:** `docs/haven-class-attribute-test`
**Status:** Complete
**Date:** 2026-09-02

## Summary

Fixes #207: the `@param haven_class` text in `survey_data()` said the argument
rebuilds the `haven_labelled` class "on every column that carried it at
import". There is no such record. `.restore_haven_class()` tests the `labels`
attribute and nothing else, so a column that never carried the class is
promoted too — an `sjlabelled`-labelled column, or one labelled by
`set_val_labels()` in data-frame mode before construction.

The repro from the issue, measured on this branch before the fix:

```r
v <- as.double(rep(1:3, 4))
attr(v, "labels") <- c(Low = 1, Mid = 2, High = 3)
df <- data.frame(id = 1:12, wt = rep(1, 12))
df$sj <- v
d <- as_survey(df, ids = id, weights = wt)

class(survey_data(d)$sj)
#> [1] "numeric"
class(survey_data(d, haven_class = TRUE)$sj)
#> [1] "haven_labelled" "vctrs_vctr"     "double"
```

Issue #207 offered two answers: add a provenance record, or keep the attribute
test and document it honestly. The user chose the second. The attribute is the
only thing `.restore_haven_class()` can see. A provenance record would need new
state that survives every write to the `data` property, plus rename and select
lifecycle wiring, and it would buy nothing: the promotion is opt-in and drops
no data.

**No behaviour changes.** Documentation, an internal comment, and three new
test rows.

One correction to the issue's framing. §XII.5 of the archived spec is scoped
to the strip — "The strip moves a column from the first convention to the
second" — and that sentence stays true. It does not describe
`haven_class = TRUE`, which is the opt-in reverse route. So §XII.5 took a
dated clarification rather than a reversal.

A second wrong provenance claim turned up in the same roxygen block while
fixing the first. The `@return` text said a column "arrived as
`haven_labelled_spss`" is returned as `haven_labelled_spss`. The code tests
for `na_values` or `na_range`, not for how the column arrived, so that clause
is now written the way the code works.
