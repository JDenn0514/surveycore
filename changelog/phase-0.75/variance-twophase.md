# feat(variance): implement two-phase variance engine and dispatch

**Date**: 2026-02-24
**Branch**: feature/variance-twophase
**Phase**: Phase 0.75

## Changes

- Implement the two-phase variance engine in `R/06-variance-twophase.R`:
  `.twophasevar()` (general engine with `"full"` / `"approx"` / `"simple"` methods),
  `.twophase_phase1_var()`, `.twophase_phase2_var()`, `.compute_phase2_probs()`,
  `.twophase_build_inputs()`, `.twophase_mean()`, `.twophase_total()`, `.twophase_df()`
- Remove the twophase rejection block from `R/06-variance-dispatch.R`; add dispatch
  branches in `get_means()` and `get_totals()` routing `survey_twophase` to the new engine
- Update roxygen for `get_means()` and `get_totals()`: remove "not yet supported" language;
  add `@section Variance estimation` entry covering all three two-phase methods
- Extend `make_survey_data(design = "twophase")` with `phase2_frac` parameter and
  `phase1_prob` / `phase2_prob` columns
- Add oracle tests against `survey::svymean` / `survey::svytotal` using `survival::pbc`
  (full and approx methods) and `survival::nwtco` (stratified Phase 2)
- Update `VENDORED.md` with four new function-level attribution entries for the
  vendored two-phase variance functions
- Add `surveycore_error_full_requires_phase2` to `plans/error-messages.md`
