# feat(analysis): dispatch get_*() over survey_collection

**Date**: 2026-04-21
**Branch**: feature/survey-collection-dispatch
**Plan**: survey-collection (PR 2)

## Changes

- Add `.dispatch_over_collection(fn, collection, ..., .id, .on_missing)`
  helper in `R/survey-collection.R`. Iterates over `collection@surveys`,
  calls `fn()` per survey forwarding NSE args via `...`, collects results,
  and returns a single `bind_rows()`-combined tibble with an `.id` column.
  Handles C5 (variable not found under `.on_missing = "error"`), C6 (all
  surveys skipped), C7 (`.id` collides with a result column), C9 (message
  listing skipped surveys under `.on_missing = "skip"`), C13 (invalid
  `.id`), and C14 (bind-type mismatch). Restores the first result's S3
  class on the combined output.
- Add `.warn_on_meta_divergence(per_survey_meta)` helper. Iterates over
  `{group, x}` × `{value_labels, variable_label, question_preface}` slots
  in each survey's `.meta` and emits
  `surveycore_warning_collection_meta_diverges` (C11) listing every
  variable with heterogeneous metadata. Warning fires at most once per
  dispatch call.
- Carry over `.meta` onto the combined result: top-level fields from the
  first survey's `.meta` (for back-compat with single-survey consumers);
  new `per_survey` and `collection` keys exposing every survey's original
  `.meta` and the collection's membership + per-survey S7 class names.
- Add dispatch branch to every analysis `get_*()` as the literal first
  line of the function body (9 functions total): `get_means()`,
  `get_totals()`, `get_freqs()`, `get_quantiles()`, `get_ratios()`,
  `get_corr()`, `get_diffs()`, `get_t_test()`, `get_pairwise()`. Each
  signature gains two post-`...` named-only control args:
  `.id = ".survey"` and `.on_missing = "error"`. Single-survey callers
  see no behavioural change; passing a `survey_collection` dispatches to
  the helper.
- Add C12 guards as the literal first lines of `survey_glm()` (in
  `R/glm.R`) and `get_anova()` (in `R/glm-anova-dispatch.R`) raising
  `surveycore_error_collection_not_supported_by_fn` with a message
  pointing users to `lapply(coll@surveys, ...)`. Collection dispatch is
  not supported for regression because per-survey GLMs do not admit a
  meaningful `bind_rows` combination.
- Modify `.resolve_tidy_select()` in `R/utils.R` to catch
  `vctrs_error_subscript_oob` from `tidyselect::eval_select()` and
  re-raise it as
  `surveycore_error_variable_not_found` (C10). Centralises C10 for all
  nine `get_*()` functions; replaces per-function `tryCatch` blocks.
- Add nine new error/warning classes to `plans/error-messages.md`:
  C5 `surveycore_error_collection_variable_not_found_in_survey`,
  C6 `surveycore_error_collection_all_surveys_skipped`,
  C7 `surveycore_error_collection_id_collision`,
  C9 `surveycore_message_collection_surveys_skipped`,
  C10 `surveycore_error_variable_not_found`,
  C11 `surveycore_warning_collection_meta_diverges`,
  C12 `surveycore_error_collection_not_supported_by_fn`,
  C13 `surveycore_error_collection_invalid_id`,
  C14 `surveycore_error_collection_bind_type_mismatch`.
- Add `.precheck_vars_present()` helper to `R/analysis-helpers.R` used by
  dispatch to report missing variables against each survey's `@data`
  names before tidyselect runs.
